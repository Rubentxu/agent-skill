# Lente C4 — arquitectura implementada, solo CogniCode

La única fuente arquitectónica es el **análisis de código a través de CogniCode CLI/MCP**. No leer directamente código, manifiestos, Terraform, Dockerfiles, configuraciones, tests, ADR o documentación; tampoco tomarlos como evidencia si el buscador de CogniCode los devuelve. [Contrato](../investigation-contract.md).

## Preguntas activas

- **C1**: ¿qué frontera del sistema y qué actores/sistemas externos están demostrados por rutas de código, superficies públicas o interacciones implementadas? Si los actores no pueden derivarse, etiquetarlos `UNKNOWN`, no inventarlos.
- **C2**: ¿qué unidades ejecutables separadas y stores existen realmente? Usar consultas sucesivas de CogniCode a entradas ejecutables, bootstrap, inicialización de servicios, conexiones y llamadas. Una carpeta, crate o dependencia **no** es un contenedor.
- **C3**: ¿qué componentes colaboran dentro de una unidad demostrada? Investigar servicios/handlers/repositorios, sus símbolos y aristas, y pedir a CogniCode fragmentos relevantes de **cada extremo**.
- **Dinámico/despliegue**: solo cuando CogniCode presente evidencia de ese plano; `calls`/`imports` no demuestran procesos, protocolo, orden temporal ni topología de deployment.

## Bucle de profundización

Primero consultar panorama, después subgrafos/símbolos concretos, y finalmente código contextual devuelto por CogniCode para contrastar cada afirmación. Si se pide zoom C3 o «más detalle», **añadir consultas** enfocadas. Ante ambigüedades, reconsultar; si CogniCode no puede resolverlas, registrar `PARTIAL/UNKNOWN` sin otras herramientas.

## Modelo y resultados

Cada componente y relación lleva `claim_id`, `query_id`, símbolos, código de referencia cuando se facilite y `plane` (`static|runtime|deployment`). Una inferencia se declara, nunca se dibuja como hecho corroborado. Generar Mermaid C4, Structurizr o LikeC4 desde ese modelo; validar formato, semántica y fidelidad **por separado**. Un diagrama anterior es material editable/curado, no evidencia.

Véanse [evidence.md](../evidence.md), [scan.md](../scan.md) y los formatos registrados.
