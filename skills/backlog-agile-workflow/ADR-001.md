# ADR-001 — Backlog.md como única autoridad, skill como router de flujo ágil

**Estado:** aceptado para la implementación inicial (2026-10-28).

## Contexto

Backlog.md proporciona archivos Markdown con persistencia, CLI, dependencia de tareas, datos JSON e instrucciones para agentes. Replicar su gestor en Python, crear un estado separado o obligar a usar MCP añadiría divergencia y tareas de mantenimiento sin valor.

## Decisión

- Una skill portable y autodetectable: router de intención → 1–2 lentes → siguiente acción; contexto reevaluable por turno.
- Backlog.md CLI/MCP oficial es dueño exclusivo de crear/editar tareas, decisiones, documentos, milestones y estados.
- Los scripts de esta skill **solo leen catálogos o instantáneas JSON ya entregadas** y producen recomendaciones, sin subprocess, shell, red, persistencia de sesión o escrituras sobre aplicaciones.
- Las opciones avanzadas con efectos Git y `onStatusChange` se inspeccionan previamente; `apply` no equivale a ejecución.
- La elegibilidad `isReady` se toma del corpus visible de la CLI; nunca se infiere a partir de una descripción.
- El ciclo ágil ligero no requiere reuniones, sprints fijos ni velocity. Los checklists AC/DoD solo se cierran sobre evidencia real.

## Consecuencias

**Ventajas:** sin lock-in de agente, sin segunda fuente de verdad, poco contexto, evaluación reproducible y capacidad de abstenerse.

**Límites:** la skill no comprueba la veracidad de una sesión declarada; los tests del router no acreditan Backlog.md instalado ni un flujo real; un agente anfitrión debe poder anunciar la skill para activarla.

**Reevaluación:** si la CLI upstream cambia sus contratos JSON, crear una nueva prueba y adaptar el parser antes de usarlo con otras versiones. No aumentar el catálogo hasta comprobar utilidad de nuevas preguntas en dos escenarios genéricos y un contraejemplo.
